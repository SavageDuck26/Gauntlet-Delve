# hashcracker scripts

Everything that drives the brute-forcer. **Workflow:** build targets ->
build/flatten vocabularies -> generate candidates -> `hashcracker crack` ->
merge hits.

## Rust modes (the engine itself)

| mode | purpose |
| --- | --- |
| `crack` | pattern / candidate brute force (`--pattern`, `--candidates`), GPU when available. |
| `bench` | time **one stage** of the CPU candidate loop (`--phase 0-6`: walk / emit / hash / probe, old path vs arena path) so optimisation follows measurements - see README -> Performance. No target set needed. |
| `mutate` | per-name edits (suffix swap, token append/prepend/merge/replace, numeric edits) inside each name's own directory. |
| `mine` | prune a dictionary to the tokens that really occur in the corpora. |
| `substitute` | **names we already have, substituted in-context** (`src/substitute.rs`, `FINDINGS.txt` #41-42): a package/type is a small self-consistent naming world, so candidates are built by swapping a component for a value observed in the same context. Pattern-driven, so the **GPU** does generation + hashing: per-type positional shapes (depth 2-5, any token position), stem+suffix, stem+number, numbers +/-3, plural siblings, directory-as-a-slot; plus a **cross-type** pass over the catalogue-wide pools *and the mined vocabularies* (`--vocab`), which is what reaches a texture named after its unit (`characters/x/x_diff`). Measured: 131 M candidates in 0.4 s per-type, 4.45 G in 12.5 s cross-type (~350 M/s, ~50x the CPU version). Knobs: `--by-package`, `--depth`, `--top`, `--vocab`, `--cpu`. |


**Start one engine at a time**: two instances halve each other's GPU/CPU
throughput.

| `make_target_patterns.py` | `data/vocab/family/target_patterns.txt` - one **pattern per unresolved target**, derived from its closest-by-body-size resolved names with the trailing tokens cut and replaced by `%n`/`%m`/`%x` (`FINDINGS.txt` #43.2b). Turns a per-family sweep into a per-target one: 949 templates cover colosseum, rooms, quilts, prefabs and menu at once. |
| `make_unit_vocab.py` | `unit_*.txt` - block piece grammar `<root>/d01_<env>/<cat>/<style>_<part>...`. |
| `make_unit_vocab_big.py` | `ub_*.txt` - the same with vocabularies mined from resolved names. |
| `make_recovered_vocab.py` | `recovered_names.txt` (every resolved name) + `tokens_ext.txt` (`data/names.txt` plus leaf/path tokens mined from those names) - the inputs for the per-cycle `hashcracker mutate` phase (`FINDINGS.txt` #33). |
| `derive_tex_siblings.py` | `derived_tex.txt` - every unit/decal/prop/block we hold **plus its `_diff`/`_norm`/`_spec` maps**, the parent of every map (both directions), and the `<stem>_<NN>_<suffix>` shape where the number sits *inside* the pair (1,358 stems; the number vocabulary is read from the catalogue like the namespaces - `01`, `02`, `2c`, ... - FINDINGS 60.17, which found two names that the append/strip/swap sweep provably cannot reach). Seeds, namespaces and numbers are discovered from the data, and the suffix list is the canonical `data/suffixes.txt`, so it is never narrower than `mutate`'s suffix step - but it costs ~2 s instead of a mutate cycle, so it is a cheap first phase before `mutate`. Validated by re-deriving the map names we already hold: **100 % recall** (453/453) and by re-finding both `caves_dragon_bones_01_{diff,norm}`. |
| `make_loc_slugs.py` | `data/vocab/loc_slugs.txt` - every 1-4 word n-gram of the game's own display text (`localization/game_strings.strings`, 91,936 values) that starts on a capitalised word, in glued and underscored form (13,346 forms). This is the vocabulary the icon words are made of: **the icon word is the glued slug of a display string** - "More of Thor" -> `hud/action_icons/warrior_ultimate_moreofthor`, "Dryad's Song" -> `elf_ultimate_dryadssong`, "Heart of Vlad" -> `equippables_icons/relic_heart_of_vlad`. Sweeping it reproduces **28 names we already held** across every icon sub-family, which is why the rule is trusted (FINDINGS #60.19). Needs the export folder; `--export`, `--max-words`, `--max-len`. |
| `derive_number_siblings.py` | `derived_num.txt` - the index rule applied to **everything we hold** (all 6.2k names) in **four passes**, covering every combination of *is there an index* x *is it glued on or a separate token*: **replace** (`arena01`->`arena02`), **append** (`decals/moss`->`moss_2`/`moss2`, `<mod>_<nn>`->`<mod>_<nn>_2`), **strip** (`hit_offset2`->`hit_offset`) and **shape** (`caves_arena01`->`caves_arena_01`, `hit_offset_2`->`hit_offset2`). `mutate`'s numeric step only rewrites a whole numeric token, so it misses all of this. Knobs: `--range LO-HI` (default `1-10`; `0-99` wide) and `--pairs` (two runs at once). Leaf-only by design (`d01_<env>` dirs are fixed). ~275k candidates at 1-10 -> a cheap phase before `mutate`. Validated by positive control: the 52 X/X2-style pairs and all 67 stripped bases in the catalogue are regenerated (100 %). |
| `make_tokens_big.py` | The wide token list for big runs: mines `recovered_names.txt` + `data/names.txt` + `lua_strings.txt` + `events.txt` + `bundle_words.txt` + the Stingray docs into `tokens_big.txt` (ranked by frequency, `--max-tokens`, default 80k). Cost of a mutate run grows linearly with this list (`FINDINGS.txt` #34). |
